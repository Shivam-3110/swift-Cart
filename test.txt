================================================================
  1. AUTH SERVICE  (http://localhost:3000)
================================================================

----------------------------------------------------------------
1.1  Register a new USER
----------------------------------------------------------------
POST http://localhost:3000/api/auth/register
Content-Type: application/json

{
  "username": "testuser",
  "email": "testuser@example.com",
  "password": "Password@123",
  "fullName": {
    "firstName": "Test",
    "lastName": "User"
  },
  "role": "user"
}

Expected: 201
{
  "message": "User registered successfully",
  "user": {
    "id": "<userId>",
    "username": "testuser",
    "email": "testuser@example.com",
    "fullName": { "firstName": "Test", "lastName": "User" },
    "role": "user",
    "addresses": []
  }
}

----------------------------------------------------------------
1.2  Register a new SELLER
----------------------------------------------------------------
POST http://localhost:3000/api/auth/register
Content-Type: application/json

{
  "username": "testseller",
  "email": "testseller@example.com",
  "password": "Password@123",
  "fullName": {
    "firstName": "Test",
    "lastName": "Seller"
  },
  "role": "seller"
}

Expected: 201 — same shape as above with role: "seller"

----------------------------------------------------------------
1.3  Register — duplicate username/email (conflict)
----------------------------------------------------------------
POST http://localhost:3000/api/auth/register
Content-Type: application/json

{
  "username": "testuser",
  "email": "testuser@example.com",
  "password": "Password@123",
  "fullName": { "firstName": "Test", "lastName": "User" },
  "role": "user"
}

Expected: 409
{ "message": "Username or email already exists" }

----------------------------------------------------------------
1.4  Login as user
----------------------------------------------------------------
POST http://localhost:3000/api/auth/login
Content-Type: application/json

{
  "email": "testuser@example.com",
  "password": "Password@123"
}

Expected: 200
{
  "message": "Logged in successfully",
  "user": { "id": "<userId>", "username": "testuser", "role": "user", ... }
}
NOTE: Save the token from the cookie or response for subsequent requests.

----------------------------------------------------------------
1.5  Login as seller
----------------------------------------------------------------
POST http://localhost:3000/api/auth/login
Content-Type: application/json

{
  "email": "testseller@example.com",
  "password": "Password@123"
}

Expected: 200 — role: "seller"

----------------------------------------------------------------
1.6  Login — wrong password
----------------------------------------------------------------

{
  "email": "testuser@example.com",
  "password": "WrongPassword"
}

{ "message": "Invalid credentials" }

  2. PRODUCT SERVICE  (http://localhost:3001)
================================================================
NOTE: All seller routes require SELLER_TOKEN from step 1.5

----------------------------------------------------------------
2.1  Create a product (seller only, multipart/form-data)
----------------------------------------------------------------
POST http://localhost:3001/api/products
Authorization: Bearer <SELLER_TOKEN>
Content-Type: multipart/form-data

Fields:
  title        = "Mechanical Keyboard"
  description  = "RGB backlit mechanical keyboard with Cherry MX switches"
  priceAmount  = 4500
  priceCurrency= "INR"
  images       = <attach 1-5 image files>

Expected: 201
{
  "message": "Product created",
  "data": {
    "_id": "<productId>",
    "title": "Mechanical Keyboard",
    "price": { "amount": 4500, "currency": "INR" },
    "seller": "<sellerId>",
    "stock": 0,
    "images": [ { "url": "...", "thumbnail": "...", "id": "..." } ]
  }
}
NOTE: Save <productId> for all subsequent product/cart/order tests.

----------------------------------------------------------------
2.2  Create product — unauthorized (user role)
----------------------------------------------------------------

Authorization: Bearer <USER_TOKEN>

{ "message": "Forbidden: Insufficient permissions" }

  "totals": { "itemCount": 0, "totalQuantity": 0 }
}

}

{

================================================================
  5. PAYMENT SERVICE  (http://localhost:3004)
================================================================
PREREQUISITE: A PENDING order must exist. Razorpay test credentials
              must be set in Payment/.env.

----------------------------------------------------------------
5.1  Initiate payment for an order
----------------------------------------------------------------
POST http://localhost:3004/api/payments/create/<orderId>
Authorization: Bearer <USER_TOKEN>

Expected: 201
{
  "message": "Payment initiated",
  "payment": {
    "_id": "<paymentId>",
    "order": "<orderId>",
    "razorpayOrderId": "order_XXXXXXXXXX",
    "status": "PENDING",
    "price": { "amount": 22495, "currency": "INR" }
  }
}
NOTE: Save razorpayOrderId, and use Razorpay test dashboard to get
      a test paymentId and signature for step 5.2.

----------------------------------------------------------------
5.2  Verify payment (after Razorpay checkout)
----------------------------------------------------------------
POST http://localhost:3004/api/payments/verify
Authorization: Bearer <USER_TOKEN>
Content-Type: application/json

{
  "razorpayOrderId": "order_XXXXXXXXXX",
  "paymentId": "pay_XXXXXXXXXX",
  "signature": "<hmac_sha256_signature>"
}

Expected: 200
{
  "message": "Payment verified successfully",
  "payment": { "status": "COMPLETED", "paymentId": "pay_XXXXXXXXXX", ... }
}

----------------------------------------------------------------
5.3  Verify payment — invalid signature
----------------------------------------------------------------
POST http://localhost:3004/api/payments/verify
Authorization: Bearer <USER_TOKEN>
Content-Type: application/json

{
  "razorpayOrderId": "order_XXXXXXXXXX",
  "paymentId": "pay_XXXXXXXXXX",
  "signature": "invalidsignature"
}

Expected: 400
{ "message": "Invalid signature" }

----------------------------------------------------------------
5.4  Verify payment — payment record not found
----------------------------------------------------------------
POST http://localhost:3004/api/payments/verify
Authorization: Bearer <USER_TOKEN>
Content-Type: application/json

{
  "razorpayOrderId": "order_NONEXISTENT",
  "paymentId": "pay_XXXXXXXXXX",
  "signature": "<valid_signature_for_above>"
}

Expected: 404
{ "message": "Payment not found" }

================================================================
  7. AI BUDDY  (http://localhost:3006 — WebSocket / Socket.IO)
================================================================
NOTE: Connect using Socket.IO client. The JWT must be present as
      an httpOnly cookie named "token" (set during login).
      You can test with the Socket.IO client library or Postman
      WebSocket with cookie header.

----------------------------------------------------------------
7.1  Connect — authenticated user
----------------------------------------------------------------
Connect to: ws://localhost:3006
Cookie: token=<USER_TOKEN>

Expected: Connection established (no error event)

----------------------------------------------------------------
7.2  Connect — no token
----------------------------------------------------------------
Connect to: ws://localhost:3006
(no cookie)

Expected: Connection refused with error "token not found"

----------------------------------------------------------------
7.3  Connect — invalid token
----------------------------------------------------------------
Connect to: ws://localhost:3006
Cookie: token=invalidtoken

Expected: Connection refused with error "Invalid token"

----------------------------------------------------------------
7.4  Send a product search message
----------------------------------------------------------------
Event:   message
Payload: "I need a laptop for programming under 70000 rupees"

Expected response event: message
Payload (example):
  "Here are some laptops I found under ₹70,000: ..."
  (Agent calls search_product tool internally, returns AI response)

----------------------------------------------------------------
7.5  Add product to cart via AI
----------------------------------------------------------------
Event:   message
Payload: "Add the first laptop to my cart with quantity 1"

Expected response event: message
Payload (example):
  "I've added [product name] to your cart!"
  (Agent calls addproducttocart tool internally)

----------------------------------------------------------------
7.6  General shopping question (no tool call)
----------------------------------------------------------------
Event:   message
Payload: "What is the return policy?"

Expected response event: message
Payload: Conversational AI response (no tool invoked)
